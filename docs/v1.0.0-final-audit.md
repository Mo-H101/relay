## 1. Release blockers

### Blockers (would prevent tagging v1.0.0)

- **B1 — OpenAI account quota (external).** Every OpenAI completion returns
  `HTTP 429` until billing is restored (`docs/blockers-before-public-release.md`
  §1). This is an **environmental/account blocker, not a code defect**: the
  error path is correct and tested. Until restored, the gateway is
  **NVIDIA-only in practice**. Whether this blocks the tag is a business
  decision: the release can be tagged as NVIDIA-ready with OpenAI
  documented as pending; full two-provider GA waits on B1.
- **No engineering blockers found.** All P6.1–P6.4 gates are green: suite
  passes, CI pipeline in place, readiness report and checklist refreshed,
  `.env.example` documents the full configuration surface, Windows and
  at-rest provider-secret behavior documented, `openai` pinned.

### Warnings (should be known/addressed before GA; none block the tag)

- **W1 — Version vs tag mismatch.** Package version is `0.1.0`
  (`app/__version__.py`, mirrored by pyproject dynamic version and
  `relay --version`). The v1.0.0 tag must be paired with a version bump to
  `1.0.0` (or a deliberate `0.x` release decision) at tag time.
- **W2 — `docs/configuration.md` omits 9 env vars.** `ANTHROPIC_ENABLED`,
  `ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL_PRIORITY`, `GEMINI_ENABLED`,
  `GEMINI_BASE_URL`, `GEMINI_MODEL_PRIORITY`, `OLLAMA_ENABLED`,
  `OLLAMA_MODEL_PRIORITY`, `RELAY_DATA_DIR` are absent from the file the
  README bills as "every environment variable". `.env.example` now covers
  all 98 parsed vars (verified against `config.py`), so this is a doc
  completeness gap, not a behavior gap.
- **W3 — At-rest provider-secret protection is a deployment requirement,
  not a code feature.** With `RELAY_KEYRING=true` provider keys are
  encrypted by the OS backend; otherwise they fall back to plaintext
  `.env` (0600 on POSIX only). Documented in `docs/security.md`
  ("At-rest protection of provider secrets") and cross-referenced from
  `docs/deployment.md`. Deployments must enable a working keyring or
  protect `.env` at rest.
- **W4 — Deployed-profile decisions are open** (from
  `blockers-before-public-release.md` §4–§6): pin
  `NVIDIA_MODEL_PRIORITY`/`OPENAI_MODEL_PRIORITY` to invocable models;
  decide retry-hardening knobs; ship with `RELAY_API_KEY` and
  `PERSISTENCE_ENABLED=true`. These are operator choices, not code gaps.
- **W5 — Deprecated provider shims remain** (`app/providers/nvidia.py`,
  `openai.py`, `lmstudio.py`). Kept through v1.0.0 by the approved P6.3
  decision; only tests import them; runtime resolves via the registry.
  Removal is a post-release cleanup item.
- **W6 — 18 tests skip by design.** 10 POSIX permission-mode checks (now
  executed on Linux CI), 5 real-LM-Studio checks (need
  `LMSTUDIO_REAL_BASE_URL` + a running LM Studio), 3 conformance
  `check_model()` skips (providers without that surface).
- **W7 — 16 planning docs untracked** in the repo (P4.2–P6.4 plans). Kept
  untracked by policy; they are not part of the release artifact.
- **W8 — Stale comment** in `app/providers/registry.py:197-199`
  ("until P4.2 wires the remaining clients into routing") while
  `RUNTIME_READY` already includes all six providers. Cosmetic.

### Future improvements (explicitly deferred, tracked in the master plan)

- **F1 — Provider-config swap** into `platform.db` (`providers` table) with
  runtime `config_store`; config is currently `.env`-only.
- **F2 — Connected applications:** labeled keys × `request_log` replacing
  the in-memory `client_tracking` store.
- **F3 — `availability.json` write retirement** in favor of the persisted
  `model_status` table.
- **F4 — Onboarding DX commands:** `relay status`, `relay providers list`,
  `relay models`, `relay config`.
- **F5 — Broader CI:** add macOS, more Python versions, and a real-provider
  smoke job as capacity allows.

## 4. Security validation

| Area | Status | Evidence |
|---|---|---|
| Secret handling | **Pass** | Raw Relay keys returned exactly once then never persisted; `platform.db` holds only scrypt `key_hash`/`key_salt`/`kdf`; provider keys in keyring (encrypted by backend) or `.env` fallback (documented at-rest requirement, W3) |
| Redaction | **Pass** | `app/services/redaction.py` masks key names, known secret shapes (`sk-`, `nvapi-`, `rl_`), and `Authorization`/`X-Relay-API-Key` headers; provider error bodies stripped via `safe_error_body`; redaction shared across wizard, clients, health checker |
| Permissions | **Pass (OS-dependent)** | `platform.db` (+ `-wal`/`-shm`/`.corrupt-*.bak`) and `.env` tightened to `0600` on POSIX; Windows relies on user-profile ACL (documented in `docs/security.md`); permission tests run on Linux CI |
| Key lifecycle | **Pass** | create → active → expired/revoked → prune; `relay keys add/remove/rotate/prune` + `/admin/keys`; rotation prints new key once and revokes original in the same op; grace-window pruning |
| Audit logging | **Pass** | Durable `events` table (schema v5); redacted at write time; hot-path auth is best-effort, admin paths fail-visible; `relay events` + `GET /admin/events`; retention bound by `PERSISTENCE_RETENTION_DAYS` |
| Failure behavior | **Pass** | Auth fails closed; keyring `get` swallows errors and returns `""` (degrade), `set`/`remove` raise; event-log write failure counted in metrics, never breaks the request; provider errors bounded/retried with timeout budget |
