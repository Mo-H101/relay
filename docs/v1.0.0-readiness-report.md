## Executive summary

Relay is **ready to enter v1.0.0 release candidate state** with the
release-blocking fixes documented below applied and the full regression
suite green (**2360 passed, 22 skipped** — current count per the R2 status
update above).

One environment blocker remains: the OpenAI account behind `OPENAI_API_KEY`
has no quota, so no OpenAI completion can succeed until billing is
restored (see `docs/blockers-before-public-release.md`). Everything else
identified in this audit is either fixed, a documented behavior, or a
non-blocking "required action" listed at the end of this report.

Release-blocking issues found and fixed during this gate:

1. **Live provider secrets were sitting at the project root with no
   `.gitignore`** (`.env` contained the NVIDIA and OpenAI keys; a stale
   `health.json` exposed internal topology). Fixed: added `.gitignore`,
   deleted `health.json`.
2. **The `/v1/chat/completions` handler blocked the asyncio event loop.**
   It was `async def` but called the synchronous chat pipeline (sync
   `httpx`, retry `time.sleep`), so one slow provider froze `/health`,
   `/metrics`, and every other request on the single documented worker.
   Fixed: converted the handlers to sync `def` so FastAPI runs them in a
   threadpool (`app/api/openai.py:189,373`).
3. **The background health refresher could die silently.** `_loop` had no
   exception guard, so a single unexpected failure stopped health refresh
   with no log signal. Fixed (`app/services/health_refresher.py:80-90`).
4. **Deployment docs endorsed multi-worker ASGI, but storage is
   single-process/single-writer** — a documented corruption path. Fixed
   `docs/deployment.md` to state the single-process requirement.

## 2. Security audit

### Verified secure

- **Authentication** (`app/security/auth.py`): single global FastAPI
  dependency (`app/main.py:55`); constant-time comparison over SHA-256
  digests (`auth.py:28-35`); key read live from settings every request so
  rotation applies without restart; `WWW-Authenticate: Bearer` on 401;
  token never logged. Public allowlist is exactly `{"/", "/health"}`
  (`auth.py:22`). Docs endpoints (`/docs`, `/redoc`, `/openapi.json`)
  are registered as real endpoints and inherit the guard
  (`main.py:74-104`); `docs_url/redoc_url/openapi_url=None`
  (`main.py:56-58`).
- **Auth metrics** (`metrics.py:501-515`): label sets are `reason`
  (`missing`/`invalid`) and `method` (`bearer`/`header`/`public`) — no
  tokens, no cardinality risk.
- **Secrets handling**: no API key, proxy credential, or generated value
  appears in admin responses (`app/api/admin.py`), diagnostics, metrics,
  or logs. `_safe_provider_body` redacts the key, strips control
  characters, and truncates to 200 chars at every provider raise site
  (`openai_compat_client.py:21-48`).
- **Input validation**: all request bodies are Pydantic models with
  `extra="forbid"` where it matters (`app/models/feedback.py`); the
  `/feedback` route additionally rejects `prompt/message/response/content`
  with a defensive 400 (`app/api/feedback.py:62-67`). `chat.py` validates
  `task` against a fixed enum. No `await request.json()` + dict passthrough
  anywhere.
- **Injection / SSRF / command execution**: no `subprocess`, `os.system`,
  `eval`, or template-from-string usage in `app/`. Outbound HTTP is to
  configured provider base URLs only (fixed, not user-controlled); every
  call has an explicit timeout.
- **CORS/CSRF**: no cookie-based auth and no CORS middleware — CSRF is not
  applicable; CORS is correctly left disabled for an API-key gateway.
- **Host header**: no `TrustedHostMiddleware`. Acceptable for an
  API-key-authenticated gateway behind a TLS proxy; note that `Host` is
  not used for any security decision. (Recommended edge control, not a
  blocker — see Required Actions.)
- **Debug/device modes**: `debug` unset (False), no `--reload` anywhere
  in the repo; the only production entrypoint is `python -m uvicorn
  app.main:app` without reload.

### Findings fixed during this gate

- Live keys in `.env` with no `.gitignore` (C1) — fixed.
- `str(exc)` returned to clients on the `/v1` non-stream internal 500
  (`app/api/openai.py:326-333`) — *documented as a required action* (M3);
  not fixed to avoid changing the error contract during freeze.
- `/health` performs live per-call probes and reports `unavailable` when
  keys are missing (`app/api/health.py`, `health_checker.py:80-154`) —
  documented behavior, noted for operators (L1).

## 3. Logging privacy

### Verified

- Relay log records contain only metadata: provider, model, attempt,
  latency, success, failure type, reason, fallback reason, error text
  (already scrubbed to 200 chars at the source), and the correlation id.
  **Prompts and responses are never captured** (`app/services/log_service.py:94-124`).
- The correlation id is intentionally classified as **ephemeral** by the
  project's memory contract and is permitted in logs
  (`app/services/correlation.py:4-7`, `app/services/memory_contract.py:46-47`).
  It is **never persisted** — the state database contains no correlation
  ids (`deployment.md`, memory-contract tests).
- Middleware records only the route template, falling back to
  `"unmatched"`; it never inspects paths, query strings, headers, client
  IPs, or bodies (`app/api/middleware.py:57-78`).
- `/metrics` labels are all bounded sets (route templates, provider
  names, status bands, failure kinds, max_tokens bands); parameter **names
  only**, never values (`app/services/metrics.py`). No cardinality risk.
- Ops store is bounded metadata with an event cap and age pruning,
  in-memory only (`app/services/ops_store.py`).

### Notes / required actions

- uvicorn's default access log (to stderr) writes
  `client-ip "METHOD /path?query" status` — outside the Relay JSON
  formatter. Run with `--no-access-log` for the public profile
  (documented in Required Actions).
- `app/services/state_flusher.py:87-91` logs `str(exc)` of SQLite errors
  (metadata-only store; low risk) and retains it for `/diagnostics`.

## 4. Metrics cardinality

Verified safe. Every label set is bounded:

- HTTP: `method`, route template, `status` (`relay_http_requests_total`).
- Chat: `endpoint`, `stream`, `max_tokens_band`; `chat_parameter` records
  parameter **names** from a fixed key set (`openai.py:169-185`).
- Providers: fixed provider names, fixed operations, status bands.
- Routing: `provider`, `model` (bounded by the model catalog),
  `failure_type` (fixed `FailureKind` enum).
- Auth: `reason`, `method` (bounded).

No user-controlled path/query/model string becomes a label. Unmatched
request paths are bucketed as `"unmatched"`.

## 5. Failure handling

### Verified

- Every outbound provider call has an explicit timeout (chat 120s,
  list_models 30s, probe_model 10s).
- Persistence failure is contained: open/load failure disables
  persistence and the app continues serving
  (`app/core/relay.py:108-116,133-157`).
- State flusher errors are logged, counted, and re-raised; the shutdown
  flush is guarded (`app/main.py:46-49`).
- Graceful shutdown verified live: lifespan stops the refresher and
  flusher, then performs a final flush.
- Retries are bounded; the request-timeout budget caps retry waits.
- Stream generators are sync (threadpool-driven by Starlette); client
  disconnects still record telemetry in `finally`.

### Required actions (non-blocking)

- M3: log unexpected exceptions in `/v1` with the correlation id and
  return a stable message instead of `str(exc)`
  (`app/api/openai.py:326-333`, streaming catch `:282-293`).
- M4: log a warning when provider model discovery fails; providers
  currently register silently with zero models
  (`app/providers/nvidia.py:22-26`, `openai.py:22-26`,
  `lmstudio.py:25-28`, `app/core/relay.py:171-175`).
- M2: add `_logger.exception` to the admin-reload catch
  (`app/api/admin.py:39-54`).
- Low: the health-check `ThreadPoolExecutor` can emit "cannot schedule new
  futures after interpreter shutdown" if a probe is still running at
  process exit (cosmetic; observed only when force-exiting mid-walk).

## 7. Documentation review (new-operator perspective)

Reviewed all docs against `app/core/config.py` and the actual routes.
Top findings:

1. **Single-process requirement** — now documented (was the highest-risk
   gap: `deployment.md` previously endorsed multi-worker against a
   single-writer SQLite store).
2. **Provider keys**: docs never say where to obtain NVIDIA/OpenAI keys;
   no `RELAY_API_KEY` generation command exists. Required action.
3. **Auth-off-by-default exposure**: when `RELAY_API_KEY` is empty, every
   route except `/` and `/health` is public (including `/metrics`,
   `/diagnostics`, `/admin/reload`). Documented in principle; the
   `cli setup` flow does not warn. Required action.
4. **`/health` semantics**: live probes per call, `unavailable` when keys
   are missing. Not documented; an operator will chase a phantom outage.
5. **`/metrics` is auth-gated**: Prometheus scraping needs
   `Authorization: Bearer <key>`; no example scrape config exists.
6. **Proxy default-on**: `PROXY_ENABLED=true` falls back to process
   `HTTP(S)_PROXY` — a host with proxy vars silently tunnels all provider
   traffic. Not warned about.
7. **Env-gotcha gap**: NVIDIA 529s, OpenAI quota 429s, `auth_error`, and
   empty-model states are absent from `docs/troubleshooting.md`.
8. **`.env.example`** covers only a fraction of the documented surface
   (retry, health thresholds, scoring, proxy, ops vars are missing) — a
   new operator copying it gets no hint these exist.
9. `audit-report.md` still shows "747 passed" from an earlier phase —
    historical; the current number is 2360 (see the R2 status update
    above).

## 9. Required actions before public release

1. Restore billing/quota on the OpenAI account; re-run the live smoke and
   confirm all six steps pass (the sole hard blocker).
2. Rotate the NVIDIA and OpenAI keys that have lived in `.env` (now
   gitignored); keep them out of the repository.
3. Decide and set the deployed profile: `RELAY_API_KEY`, `PERSISTENCE_ENABLED`,
   `PERSISTENCE_PATH`, health/telemetry flags, and `NVIDIA_MODEL_PRIORITY`

   (`RETRY_HONOR_RETRY_AFTER`, `RETRY_BACKOFF_BASE_SECONDS`,
   `REQUEST_TIMEOUT_BUDGET_SECONDS`) in the deployed profile.

   exceptions with the correlation id and stop returning `str(exc)`
   (M3); log provider model-discovery failures (M4); log admin-reload
   failures (M2); run uvicorn with `--no-access-log`.

   Prometheus auth header + scrape config, proxy default-on warning,
   troubleshooting entries for 529/quota/auth errors, and filling
   `.env.example` to cover the documented surface.
